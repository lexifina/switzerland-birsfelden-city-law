## Dates

Each commit is dated at noon (Europe/Zurich) on the day the change took effect. The other dates, enacted and published, are trailers.

When a law gives no date of its own, the default rule applies: Each version is dated by the day the city's systematic collection says it took effect ("in Kraft seit / von"); municipal acts take effect on the day the act or the city sets. https://lex.birsfelden.ch/

## How the history is built

`tools/build.py` turns the corpus into this history in one pass: one commit per law, on the day it took effect. The same corpus always gives the same commit hashes. `tools/check_repo.py` reads every version back from git and compares it with the corpus. `tools/on.py` shows the law as it stood on any date. The corpus format is described in `tools/SCHEMA.md`.

## Decisions made by hand

- Each version is the consolidated text the city's systematic collection publishes, dated by its "in force from" day; when two versions share a day only the last is kept.
- Changes are credited to the entries of the act's own change table (decision, in-force day, element, CRS reference) whose in-force day falls after the previous version and on or before this one; a change whose element the table does not name is credited to every entry of that window.
- Section headings are kept together in one file per act (gliederung.md); the title, date and preamble in ingress.md; the signature block in schluss.md. Amendment markers (*) and the "Stand" date are left out.
- Annexes published only as separate PDF files are not included.
- An act's first version is credited to its original enactment only when the change table shows no change in force before it; otherwise it is the oldest version available.
- Breadth first: each added act has one current-text version, first_law null, credited to the publisher as oldest version available.
- Each added version uses the latest applicable source in-force date, comparing the current-version banner with every document amendment-table date. A later source amendment date overrides a stale banner; no retrieval date is used as an in-force date.
- Each added act is a single-file act retaining the complete source XHTML text in order, including titles, tables and editorial amendment information; only whitespace and HTML entity representation are normalized; table rows, cells and spans remain source HTML.
- Image-bearing acts, PDF-only acts and acts with separate annexes remain outside this addition pending full text and image verification.
- SRS 7.4.5-1 uses 2021-01-01 and SRS 8.8-3 uses 2009-05-19: their document amendment tables name later amendments than the API current-version banners. The contradictory banners are retained in the source evidence, and the chosen rows are quoted in the version notes.
- The unit metadata label is correctly encoded German: Vollständiger Text. No legal text changed during reviewer rework.
